# GameAsset-Forge 产品设计说明

## 一、产品背景

学生团队、独立开发者和 Game Jam 参赛者在早期游戏 Demo 开发中，经常需要快速准备一批 2D 游戏素材，包括角色、敌人、道具、地图块、UI 和背景。

普通 AI 绘图工具虽然可以生成图片，但更多是“单张图片生成”，缺少面向游戏工程的流程能力，例如素材清单规划、风格统一、Prompt 复用、素材分类、质量检查和导出结构。

GameAsset-Forge 的核心目标是将 AI 绘图能力组织成一个游戏素材生产工作流。

---

## 二、目标用户

本项目主要面向：

- 学生游戏开发团队；
- 独立游戏开发者；
- Game Jam 参赛者；
- 需要快速制作游戏 Demo 的产品、策划或开发人员；
- 不具备专业美术能力，但需要快速获得可用 2D 素材的用户。

---

## 三、用户痛点

### 1. 不知道一个 Demo 需要哪些素材

很多早期开发者只知道“我要做一个游戏”，但不知道需要哪些基础素材，例如主角、敌人、地图块、按钮、背景等。

### 2. 素材风格不统一

即使使用 AI 绘图，单独生成的图片也容易在画风、色彩、视角和背景上不一致。

### 3. 缺少工程化组织

游戏素材不仅要有图片，还需要命名、分类、路径、Prompt 记录和导出结构。

### 4. API 生图存在不确定性

真实图像生成 API 依赖网络、API Key、额度、模型能力和返回格式。为了保证项目可展示，系统需要同时提供稳定的 Demo Mode。

---

## 四、产品方案

GameAsset-Forge 采用“素材需求描述 + 结构化参数”的混合输入方式。

- 素材需求描述：表达用户想要生成的具体素材；
- 结构化参数：约束游戏类型、风格、尺寸、视角、背景和色彩主题。

系统将二者合并，生成素材蓝图和 Prompt，再通过 Demo Mode 或 API Mode 进入素材生成流程。

---

## 五、核心功能模块

### 1. 项目配置模块

收集游戏名称、游戏类型、游戏主题、美术风格、素材尺寸、游戏视角、背景要求和色彩主题。

### 2. 素材需求描述模块

允许用户输入希望生成的素材名称，系统通过规则解析将其补充到素材清单中。

### 3. Asset Blueprint 素材蓝图模块

根据游戏类型生成默认素材清单，并支持用户编辑。

### 4. Style Lock 风格锁定模块

将风格、尺寸、视角、背景和色彩主题统一注入 Prompt 生成流程，减少风格不一致问题。

### 5. Prompt Composer 模块

根据素材类型生成 Game-aware Prompt。

### 6. Demo 素材生成模块

使用内置 36 张 Pillow 程序化素材稳定演示完整流程。

### 7. API 图像生成模块

支持用户配置 API Key、API Base URL、模型名称和输出尺寸，根据 Prompt Composer 输出的 Prompt 调用图像生成服务。

当前默认支持硅基流动 API，默认模型为 Tongyi-MAI/Z-Image-Turbo。

### 8. 素材库展示模块

按角色、敌人、道具、地图块、UI 和背景进行分类展示。

### 9. 质量检查与导出模块

检查素材字段完整性、图片路径和 Prompt 记录，并导出 asset_pack.zip。

---

## 六、MVP 边界

当前 MVP 重点是验证游戏素材工作流，而不是追求商用级美术效果。

当前版本：

- 已实现 Demo Mode；
- 已实现 API Mode；
- 已实现素材库分类展示；
- 已实现质量检查与导出；
- API 生成效果取决于所选图像模型、Prompt 和服务商能力。

---

## 七、产品价值

GameAsset-Forge 的价值不在于单次生成一张图片，而在于把游戏素材生产过程拆成可管理、可编辑、可导出的流程。

它帮助用户从“我想做一个游戏”走到“我获得了一包结构清晰的游戏 Demo 素材”。

Demo Mode 保证流程稳定可展示，API Mode 提供真实 AI 生成能力，二者共同构成一个更完整的 MVP。
